01 · What is LoRA fine-tuning

Fine-tuning adapts a pre-trained model

Pre-training

Trillions of tokens. Learns general language. Months of compute — only large labs do it.

Fine-tuning

A small, specialised dataset. Learns your task, format or style. Continues training the same weights.

Wnew = Wold + ΔW

Every layer of a neural network is a weight matrix W. Fine-tuning learns the change ΔW.

A model is a stack of weight matrices. Pre-training sets them; fine-tuning nudges them for a specific job. The question LoRA answers: how do we learn ΔW cheaply?

02 · How LoRA works

Low-rank: a big matrix from two thin ones

ΔW d × d

=

B d × r

×

A r × d

With d = 4096 and r = 8:

16,777,216 → 65,536 numbers

256× fewer

The bet: the change ΔW a new task needs has a low “intrinsic rank” — the model only has to move in a few directions.

A matrix of rank r can always be written as a tall d-by-r matrix times a wide r-by-d matrix. The LoRA paper showed that ranks of 1 to 8 were often enough even for GPT-3 175B. So instead of learning ΔW directly, we learn B and A.

02 · How LoRA works

The forward pass has two branches

h = W₀x + (α/r) · B A x

x

W₀ · x (frozen)

A: d → r

r dims

B: r → d

× α/r

+

h

Only A and B get gradients. The full d × d matrix ΔW is never built during training.

The input goes through the frozen weight as usual, and in parallel through a thin bottleneck: A squeezes d dimensions down to r, B expands back to d. The two results are added. Because we compute B times (A times x), we never materialise the big ΔW.

02 · How LoRA works

Three details that make it work

B = 0

Start from the original

At step 0, BA = 0, so the model is exactly the pre-trained one. A is random so gradients can flow; if both were 0, nothing would ever learn.

× α / r

Keep the scale stable

Dividing by r keeps the update’s size steady when you change r, so the learning rate does not need re-tuning. Common: α = r or 2r.

W′ = W₀ + ΔW

Merge after training

W′ has the same shape as W₀, so inference is exactly as fast as the base model. Or keep A and B separate as a swappable adapter.

Zero-init of B means training starts at the pre-trained point instead of breaking it on step one. The alpha over r factor is a convenience for tuning. Merging is what makes LoRA free at inference time, unlike adapter methods that add layers.

03 · Implement LoRA

A LoRA layer in plain PyTorch

class LoRALayer(nn.Module):
    def __init__(self, base, r=8, alpha=16):
        super().__init__()
        self.base = base
        for p in base.parameters():
            p.requires_grad_(False)   # freeze W0
        d_out, d_in = base.weight.shape
        self.scale = alpha / r
        self.A = nn.Parameter(torch.randn(r, d_in) * 0.01)
        self.B = nn.Parameter(torch.zeros(d_out, r)) # B = 0
    def forward(self, x):
        lora = (x @ self.A.T) @ self.B.T  # d → r → d
        return self.base(x) + self.scale * lora
    @torch.no_grad()
    def merge(self):
        self.base.weight += self.scale * self.B @ self.A

Wrap, then freeze

The original layer becomes base; none of its weights train.

Two new matrices

A random and small, B all zeros. Only these train.

Add the branch

base(x) plus the scaled bottleneck output.

Merge for deployment

Fold ΔW into W0 once training is done.

This is the whole mechanism in about fifteen lines. The notebook version adds dropout, an on/off switch, Kaiming init for A, and handles GPT-2’s Conv1D, which stores its weight transposed. The tests there check three things: identical output at init, only A and B trainable, and identical output after merge.

03 · Implement LoRA

Inject it into a real model, then train

def inject_lora(model, targets, r=8, alpha=16):
    for p in model.parameters():
        p.requires_grad_(False)      # freeze everything
    for parent in list(model.modules()):
        for name, child in list(parent.named_children()):
            if name in targets:      # swap in LoRA
                setattr(parent, name, LoRALayer(child, r, alpha))

model = AutoModelForCausalLM.from_pretrained("distilgpt2")
inject_lora(model, {"c_attn"})   # GPT-2 attention q, k, v

opt = torch.optim.AdamW([p for p in model.parameters()
                         if p.requires_grad], lr=2e-3)
loss = model(**batch).loss   # labels = -100 on the prompt
loss.backward(); opt.step()

Pick target layers

Here the attention projection c_attn. In practice: all linear layers.

Higher learning rate

1e-4 to 2e-3, about 10× full fine-tuning.

Mask the prompt

Loss only on answer tokens, so the model learns to answer, not to ask.

The injection walks the module tree and replaces every layer with a matching name. That is exactly what target_modules does in peft. The training loop is ordinary PyTorch; the optimizer only receives the parameters that still require gradients, which are A and B.

Now that you know what is inside, peft is a thin, well-tested wrapper around the same idea. fan_in_fan_out tells it GPT-2 stores weights transposed, which is our transposed flag. In real projects you would add transformers Trainer or TRL’s SFTTrainer for the training loop.

These are defaults for 7B-class models with peft. For Llama-style models, all linear layers means q, k, v, o, gate, up and down projections; peft accepts the shortcut all-linear. Always validate on held-out data.

In practice

QLoRA: fine-tune big models on one GPU

W₀ is frozen, so it does not need full precision: store it in 4-bit (NF4) and train A and B in bf16. Memory for an 8B model, before activations:

Full fine-tuning (fp32 + Adam)

~128 GB

LoRA, base model in fp16

~16 GB

QLoRA, base model in 4-bit

~5 GB

QLoRA: Dettmers et al., 2023. Needs an NVIDIA GPU and the bitsandbytes library. Bars are drawn to scale.

QLoRA is the reason people can fine-tune 7B to 70B models on a single GPU. The trick only works because of LoRA: the big matrix is frozen, so it can be compressed, while the small trainable matrices stay in higher precision.

In practice

Four common mistakes

Forgetting to freeze

You are secretly doing full fine-tuning. Always check print_trainable_parameters().

Learning rate too low

A full fine-tuning rate like 2e-5 barely moves LoRA. Start around 1e-4 to 2e-4.

Wrong chat template

Instruct models expect their own conversation format. Use tokenizer.apply_chat_template.

Expecting new knowledge

LoRA is best at format, style and tasks. For large bodies of facts, combine it with RAG.

Two more from the notebook: mask the prompt tokens in the loss, and keep a validation set, because tiny datasets overfit to zero training loss. With QLoRA, reload the base model in fp16 or bf16 before merging.

Takeaways

LoRA in four lines

1

Freeze W₀ and learn ΔW = (α/r)·BA with a small rank r.

2

Train about 0.1–1% of the parameters; adapters are megabytes.

3

Start with B = 0; merge after training for zero extra latency.

4

It fits in 15 lines of PyTorch; peft does the same thing.
